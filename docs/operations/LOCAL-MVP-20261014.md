unrelated process to free a port.

## Shutdown and restart

1. Press **Ctrl+C in the frontend terminal** to stop only its Vite process.
2. Press **Ctrl+C in the backend terminal** to stop the demo launcher. Its
   temporary SQLite database is removed; any demo accounts are discarded.
3. Run the two startup commands above again. Five reviewed events are recreated;
   register a new disposable account after each backend restart.

For assistant-started servers, request that those specific demo processes be
stopped before starting your own terminals. Do not stop unrelated listeners or
use broad process-name termination commands.

## Required dependencies

- Verified interpreter: repository-root `backend/.venv/Scripts/python.exe`,
  Python **3.12.6**. Activation is unnecessary when using the explicit path.
- Existing backend environment with FastAPI, Uvicorn, SQLAlchemy, Alembic,
  bcrypt, PyJWT and the remaining `backend/requirements.txt` dependencies.
- Verified Node **24.19.0**, npm and the existing frontend `node_modules`.
  If missing, use `npm.cmd ci` from `frontend`; this is project-local installation.
- Chrome or Edge is required only for browser acceptance. Set
  `BROWSER_EXECUTABLE_PATH` to its executable if auto-detection fails.
- Unused loopback ports **8021** and **5176**, and a writable temporary directory.
- Docker, PostgreSQL and SMTP are not required for this isolated local demo.

Never install dependencies globally or substitute the default Python interpreter
without checking its dependencies. The existing environment's `pip check` passed.

The launcher overrides DATABASE_URL with a new temporary SQLite database, runs
the existing migration chain, validates the entire reviewed curated manifest,
imports five real source-backed records and checks repeat-import deduplication.
It forces email disabled and binds only to loopback. It never starts the source
registry, crawls websites or uses a live database. No accounts or credentials are
seeded; register your own disposable account.

Account changes persist between login sessions while this backend process runs.
Stopping the backend deletes its temporary database. Restarting recreates the
reviewed snapshot and requires registration again. This intentionally avoids
changing any existing PostgreSQL data or database history.

## Troubleshooting

| Symptom | Action |
| --- | --- |
| Missing `bcrypt` or application import | Use the exact repository virtual-environment interpreter and release-worktree directory above. Do not use plain `python` as a substitute. |
| Port already in use | Inspect `Get-NetTCPConnection -State Listen -LocalPort 8021,5176`. Identify the process before stopping it; preserve unrelated processes. |
| Frontend cannot reach API | Check `http://127.0.0.1:8021/health`, confirm `API_PROXY_TARGET`, then restart only Vite. Test `http://127.0.0.1:5176/api/health`. |
| Registration disappears after restart | Expected: each backend start creates a new temporary demo database. Register again. |
| Empty date-filter results | Reset filters; dates use UTC calendar boundaries, and undated records are excluded. Most snapshot records are historical. |
| No predictions or reset email | Expected unavailable behavior; no approved public prediction model or recovery endpoint is configured. |
| Consent saved but no email | Expected: the demo forces email off and launches no sending worker. Account save notices are separate. |
| Browser executable not detected | Set `BROWSER_EXECUTABLE_PATH` to installed Chrome or Edge. |
| `WinError 5` or Node `spawn EPERM` in restricted execution | Allow the isolated test process to use temporary storage/subprocesses; do not change live databases or global dependencies. |
