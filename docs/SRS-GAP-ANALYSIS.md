## Reading this matrix

- **complete**: this narrowly stated control is implemented and supported by the cited checks; it does not certify the whole SRS.
- **partial**: a working subset or scaffold exists, but acceptance is incomplete.
- **missing**: no operational implementation found; a table/role placeholder alone is not implementation.
- **unverified**: implementation/configuration exists but the specified deployment, benchmark or human acceptance evidence does not.
- The SRS assigns **Must/Should only to the 27 FR rows**. SCR, SEC and other sections have **not stated** priority. Do not invent a Must/Should label for them. Their normative language and section 16 release gates still matter.
- `SRS §...` rows below are section locators for requirements lacking IDs in the PDF, not newly invented SRS IDs.
- Implementation priority: **P0** safe demonstration/security/truth controls; **P1** required foundation or acceptance blockers on separate reviewed branches; **P2** advanced or explicitly Should work; scope changes need stakeholder approval.
- Test references are repository paths unless a named test is included. Only the verification ledger at the end records tests actually run in this session.

Path aliases to keep the table readable: **B** = `backend/app`; **BT** = `backend/tests`; **C** = `backend/modules/2.2-collector`; **SR** = `backend/modules/2.1-source-registry`; **F** = `frontend/src`; **FT** = `frontend/tests`; **OPS** = `tests/operations`; **K** = `infrastructure/kubernetes`.
